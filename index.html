How to Play

Weapons fire on their own — your job is to position. Stay alive through each floor's horde until its gate Warden drops, then bring the Warden down to descend. Do it ten times.

The run loop

01 · Survive

Ride the horde

Machines pour in and thicken over time. Your guns auto-target; you kite, thin the pack, and scoop the XP shards they drop.

02 · Level

Take an augment

Fill the XP bar to level up and pick one of three — a new weapon, a passive, or a floor-tagged skill. The offer only appears when you reach the next level.

03 · Fuse

Evolve the build

Level two matching weapons and the panel offers a fusion — one stronger weapon in place of the pair. Four slots, so every pick is a commitment.

04 · The gate

Kill the Warden

When the floor's hold expires the gate slams down and a Warden lands. It breaks through phases and never dies quietly — put it down and the floor is cleared.

05 · Descend

Go deeper

Each floor is a wholly different place — new ground, an exclusive roster of machines, a new Warden. Ten floors to the Centre of the Earth.

Between runs

Spend the web

Tokens buy nodes on the skill web; salvaged relics bolt onto your frame. This is how a frame grows run-over-run — and how you get strong enough for HELL.

Playable War-Frames

NEON REAPER ships six playable "frames" — hijacked HALCYON chassis that MOTHER boots your ghost into. They are defined in the CHARACTERS array in scripts/game.gd (lines 17-63). Each frame is a distinct build identity: a fixed signature weapon, its own integrity/speed/damage profile, and its own origin node (CORE) at the root of the shared skill web.

All numbers below are copied verbatim from the source. Movement speed in the data is a multiplier on BASE_SPEED := 115.0 px/s (scripts/player.gd:12); the effective px/s is shown for convenience. Damage is a global weapon-damage multiplier (weapons.base_damage_mult). Self-repair (regen) is integrity restored per second.

Notes on the CORE nodes

Every core_* node in SKILL_WEB (game.gd:1106-1117) has cost: 0, class minor, and empty hooks: {} — it is purely the entry point of that frame's branch of the shared skill web and grants no stats on its own. The frame-specific passives (tagged "only": "<id>", e.g. game.gd:1252-1347) hang off these cores and carry the actual bonuses:

  • SCYTHE // RIPPER SMG branch — sustained fire paid for in heat (sdmg/scdr nodes, ending in the twinfeed signature).
  • BULWARK // SENTRY POD branch — the gun outlives the frame that placed it (ends in emplace).
  • HAVOC // TESLA MINES branch — stand in the blast (ends in cluster).
  • VECTOR // PINBALL SLUG branch — one slug, every wall (ends in chainshot).
  • TEMPEST // ARC BLADES branch — more edge, less chassis (ends in rend).
  • THE COURIER // ICEBREAKER branch — the gun does no damage, so the wing buys the kill (ends in conscript).

Weapons

NEON REAPER's arsenal is defined in scripts/weapons.gd. There are 34 weapons total: 20 base skills (W_*) plus 14 fused skills (F_*, "FUSION PROTOCOL"). Each is one dictionary in the WEAPONS array, indexed by its enum value in declared order.

Global rules & scaling (constants at top of file):

  • MAX_SLOTS = 4, MAX_WEAPON_LEVEL = 8, PASSIVE_MAX_RANK = 5.
  • Cooldown / fire interval per level: interval × 0.93^(level−1) × cooldown_mult (i.e. ~7% faster each level). Signature weapons additionally multiply by sig_cdr. Evolved weapons may apply a further multiplier (see Evolved column).
  • Damage per level: dmg × (1.0 + 0.3 × (level−1)) × damage_mult (i.e. +30% base damage per level). Signature weapons additionally multiply by sig_dmg. Evolved weapons may apply a further multiplier.
  • damage_mult / cooldown_mult are live values driven by Vault loadout, passives, and conditional skill nodes.

FUSION PROTOCOL — Weapon Combinations

FUSION PROTOCOL welds two maxed-out skills into a single, stronger fused skill. The recipes live in FUSIONS in scripts/weapons.gd (each entry is {"a", "b", "into"}), and every fused skill's stats come from the corresponding entry in the WEAPONS array.

Requirement: const FUSION_LEVEL := 5. Both parent weapons (a and b) must be installed and at level 5 or higher for the fusion to be offered (available_fusions() checks lv.get(f.a) >= FUSION_LEVEL and lv.get(f.b) >= FUSION_LEVEL). Performing the fusion consumes both parents and frees a slot. Fused skills are earned only via fusion — they are never offered as raw installs (FIRST_FUSION := F_NOVA marks the start of the fused-only range in the pool logic).

Relics & Items (the Vault)

Relics are persistent gear pulled out of districts and stored in the Vault. A relic is just a {hook: value} dictionary — the same shape as a skill-web node — and loadout_mods() merges every equipped relic plus every owned skill node into one flat modifier dictionary that Main applies once at run start. Nothing here ticks per frame.

Gear belongs to the frame (runner) it was fitted to, so switching frames switches kit. Each frame carries at most RELIC_SLOTS = 3 relics. toggle_equip() fits or removes one (only if the Vault owns a copy); the first copy of a newly-granted relic auto-slots into an empty slot so the Vault is never full of gear you forgot to equip.

Rarity tiers & drop tables

RARITY_NAMES = ["SALVAGE", "MILSPEC", "BLACK ICE"] (indices 0/1/2). Each drop rolls rarity first, then walks down to a lower non-empty rarity if the rolled pool is exhausted, preferring a relic you do not yet own.

Drop sites (main.gd):

  • Wreck salvage: 10% * luck chance per wreck (first salvage of a save is guaranteed) → roll_relic() default = DROP_WRECK / TIER_WRECK.
  • Mid-run heavy unit: 55% chance → roll_relic(DROP_MIDBOSS, TIER_MIDBOSS), plus +1 token.

  • First district liberation: grants that district's from BLACK ICE at roll_tier(TIER_WARDEN).

Duplicates & stars

Owning copies earns stars, which scale only the positive hooks:

  • STAR_AT = [1, 3, 6] → 1 copy = ★, 3 = ★★, 6 = ★★★
  • STAR_SCALE = [1.0, 1.6, 2.2] (applied to beneficial hooks; e.g. a ★★★ ONYX ROUND SET is +34% damage but still only −8% speed)

Past three stars (6 copies) a duplicate is not a dead drop: it converts to +2 tokens for the frame that found it, unless it is a better condition tier, in which case it refits instead. no_stars relics (preload, symbols, backup) never scale with stars.

Achievements tied to relics

  • relic_first → "GRAVE ROBBER" (recover your first relic)
  • relic_all → "COMPLETE SET" (recover every relic in the Vault, i.e. vault.size() >= RELICS.size())

The Skill Web

NEON REAPER does not give each frame its own skill tree. Instead there is one shared lattice — a single large web of nodes that every frame can path through — plus a private "wing" bolted onto each frame's core. In scripts/game.gd, the whole board lives in the SKILL_WEB constant (nodes), WEB_LINKS (edges), and WEB_CORES (which node is which frame's root). There are 115 nodes in total: 73 shared (including the 6 cores) and 42 wing nodes (6 wings × 7 nodes each).

Frames and trees

There are 6 frames, one per entry in WEB_CORES. Each has a free, pre-owned root node (cost 0) that anchors it to the lattice:

web_nodes(runner) returns the tree a single frame can see: it walks SKILL_WEB and keeps a node only if it has no only tag (shared lattice) or its only tag matches that frame. Every other frame's wing is omitted entirely — as the code comment puts it, "six trees that differ in shape read as six trees, not one tree with locks." A node carrying only is that frame's private wing (web_is_wing()), and a wing only ever upgrades the signature weapon that frame is born holding — its bonuses use the signature-scoped keys sdmg/scdr, never the whole arsenal.

The HELL unlock node

HELL is not a fill percentage — it is a single clearance node on the web.

NodeNameClassCostEffect (hooks)
hell_keyBLACK ICE CLEARANCEnotable3dmg 0.06, armor 0.10, unlocks_hell: true

BLACK ICE CLEARANCE rings all four hub junctions (hell_key links to hb_nw, hb_ne, hb_se, hb_sw), so every frame reaches it exactly one step past its own hub. hell_unlocked() loops over WEB_CORES and returns true if any single frame owns hell_key — buying it on one frame opens HELL for the whole account, and difficulty_count() then exposes the top difficulty tier. It is a real node too, not just a gate: the dmg 0.06, armor 0.10 are meant to help you survive floor 1 on HELL.

Total cost and the (absent) cap

web_total(runner) sums the cost of every node a frame can reach, skipping the core_ roots. Because the shared lattice is a constant and every wing has the identical shape (3 minors + 3 notables + 1 keystone = 18 tokens), the total is the same for all six frames:

ComponentTokens
Shared lattice (buyable, excludes 6 cores)190
One frame's private wing18
web_total (per frame)208

There is no artificial cap: web_cap(runner) simply returns web_total(runner). A frame can fill every node it can reach; the only limiter is the tokens it has actually earned. Signature rank is now purely a HUD badge and no longer rations allocation, and HELL is gated by the hell_key node rather than by web completion.

HELL Mode

HELL is difficulty index 3 (DIFFICULTY_NAMES = ["EASY", "NORMAL", "HARD", "HELL"]). It is not NORMAL with fatter numbers — it changes what the machines *do* and it is the only tier where the floors themselves fight back. Two systems combine:

1. Floor quirks (scripts/floor_quirk.gd) — one rule per floor, the level as an opponent. These are HELL-only: apply() clears the quirk id unless Game.quirks_live() is true, and quirks_live() returns int(settings.difficulty) >= DIFFICULTY_NAMES.size() - 1 — i.e. difficulty 3. On every other tier the whole feature is inert (no tick, no draw, no cost). 2. Difficulty knobs (scripts/game.gd) — per-tier multiplier tables read once per run into enemy_manager.gd, plus the chaos "death spite" behaviour.

Every quirk's intensity is scaled by SEV = [0.85, 1.0, 1.15, 1.15], indexed by difficulty. The HELL severity is SEV[3] = 1.15 (identical to HARD's, but only HELL ever reaches it). Damage/pull/slow values below are the raw constants; multiply by _sev = 1.15 for the effective HELL number (shown where load-bearing).

Chaos "death spite" (scripts/enemy_manager.gd)

_chaos is resolved once per run in _refresh_difficulty() from DIFF_CHAOS, so on HELL _chaos = 2. Two behaviours key off it:

  • Lunge (_chaos >= 1, so HARD + HELL): a machine within dist < 96.0px of the frame closes 1.45× faster (mv *= 1.45), so kiting stops being a free answer.
  • Death spite (_chaos >= 2, HELL only, ~line 2813): when any machine dies *except* T_OVERLORD and T_SAPPER, and the enemy-shot pool has room (_shots.count < MAX_SHOTS(768) − 8), there is a 15% chance (randf() < 0.15) it fires a parting volley through _fan() toward the player — dir = (_player.position - pos[i]).normalized(), speed 190, bolt scale 0.8, colour = the machine's type colour, damage = EnemyShots.DMG(9.0) × 0.5 = 4.5 per bolt. Because it routes through _fan(), on HELL it is a 3-shot fan (DIFF_VOLLEY=3) at 0.17 rad spread, and the bolts inherit DIFF_SHOT_SPEED=1.20 (190 × 1.20 = 228 effective). Clearing a pack at point-blank still costs you something — at 15%, "punished, not forbidden".
